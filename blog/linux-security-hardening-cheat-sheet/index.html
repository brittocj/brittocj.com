Linux Security Hardening Commands Cheat Sheet: RHEL, SLES and Ubuntu

📅 October 1, 2026
⏱️ 14 min read

A Linux security baseline is not created by running a single hardening script. Enterprise security is achieved through a combination of secure configuration, least privilege, patch management, access control, monitoring, and continuous validation. This cheat sheet provides practical commands that Linux administrators can use while hardening enterprise servers running Red Hat Enterprise Linux (RHEL), SUSE Linux Enterprise Server (SLES), and Ubuntu Server.

The examples focus on common enterprise security tasks:

  • System inventory
  • User and privilege management
  • SSH hardening
  • Firewall configuration
  • SELinux/AppArmor
  • File permissions
  • Service management
  • Kernel hardening
  • Auditing and logging
  • Vulnerability checks

For the reasoning behind each control, see Linux Security Hardening: A Practical Enterprise Guide.

System Inventory Commands

Running Services

systemctl list-units --type=service --state=running
systemctl --failed
systemctl list-unit-files --state=enabled

Listening Network Ports

Always identify exposed services.

ss -lntup

Example:

tcp LISTEN 0 128 0.0.0.0:22
tcp LISTEN 0 128 0.0.0.0:443

Identify which process owns a port:

sudo ss -lntup | grep :443
sudo lsof -i :443

User Account Hardening

List Users

cat /etc/passwd
awk -F: '$7 !~ /(nologin|false)$/ {print $1,$7}' /etc/passwd

Check UID 0 Accounts

Only trusted accounts should have UID 0.

awk -F: '$3 == 0 {print $1}' /etc/passwd

Expected:

root

Create, Lock and Age Accounts

sudo useradd -m adminuser
sudo passwd adminuser
sudo usermod -L username
sudo usermod -U username
sudo chage -l username
sudo chage -M 90 username

Example output:

Maximum password age: 90 days

sudo Privilege Management

sudo visudo
visudo -c
sudo -l

Example group access:

%linux-admins ALL=(ALL) ALL

Create the admin group and add the user:

sudo groupadd linux-admins
sudo usermod -aG linux-admins adminuser
Always validate: visudo -c before saving. A syntax error in /etc/sudoers locks out every administrator on the box.

SSH Security Hardening

SSH configuration lives at /etc/ssh/sshd_config.

sudo cp /etc/ssh/sshd_config \
/etc/ssh/sshd_config.backup
sudo sshd -t
ControlSetting
Disable root loginPermitRootLogin no
Key-only authenticationPasswordAuthentication no
Enable public keysPubkeyAuthentication yes
Restrict to a groupAllowGroups linux-admins

Restart SSH per distribution:

# RHEL / SLES
sudo systemctl restart sshd

# Ubuntu
sudo systemctl restart ssh

Generate and distribute keys, and secure the SSH directory:

ssh-keygen -t ed25519
ssh-copy-id user@server
chmod 700 ~/.ssh
chmod 600 ~/.ssh/*

Firewall Hardening

Ubuntu UFW

sudo ufw status verbose
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 443/tcp
sudo ufw allow from 10.10.10.0/24 \
to any port 22
sudo ufw delete allow 443/tcp
sudo ufw enable

Allow your administration path before enabling the firewall, otherwise you risk locking yourself out.

RHEL / SLES firewalld

sudo firewall-cmd --state
sudo firewall-cmd --list-all
sudo firewall-cmd \
--permanent \
--add-service=https
sudo firewall-cmd \
--permanent \
--add-service=ssh
sudo firewall-cmd --reload

AppArmor Hardening (Ubuntu/SLES)

sudo aa-status
sudo aa-status --profiles
sudo aa-enforce /etc/apparmor.d/profile
sudo aa-disable profile

File Permission Auditing

Check Sensitive Files

ls -l /etc/passwd
ls -l /etc/shadow
ls -l /etc/sudoers

Expected:

-rw-r-----  1 root root /etc/shadow

Find World Writable Files and Directories

sudo find / \
-xdev \
-type f \
-perm -0002

sudo find / \
-xdev \
-type d \
-perm -0002

Find SUID Files

SUID binaries execute with owner privileges. Review carefully:

sudo find / \
-perm /4000 \
-type f

Secure Temporary Directories

findmnt /tmp
findmnt /var/tmp

Possible hardening options:

nodev
nosuid
noexec

Example /etc/fstab entry:

tmpfs /tmp tmpfs defaults,nodev,nosuid 0 0

Test carefully before production deployment, and validate against the workload before adding noexec.

Kernel Security Parameters

sysctl -a
sysctl net.ipv4.ip_forward
sudo sysctl -w net.ipv4.ip_forward=0

Persistent configuration:

/etc/sysctl.conf
/etc/sysctl.d/

Apply:

sudo sysctl --system
Careful: a router, VPN gateway, load balancer, or Kubernetes node legitimately needs net.ipv4.ip_forward=1. Never apply a copied sysctl.conf without confirming the server's role.

Disable Unnecessary Services

systemctl list-unit-files
sudo systemctl disable --now service_name
sudo systemctl disable --now telnet.socket

Final Thoughts

Linux security hardening is not about applying hundreds of commands blindly. A secure enterprise Linux server follows a few fundamental principles:

  • Install only required software.
  • Expose only required network services.
  • Use individual accounts and least privilege.
  • Protect privileged access.
  • Keep mandatory access controls enabled.
  • Monitor and audit important activity.
  • Patch continuously.
  • Validate security posture regularly.

The strongest Linux administrators are not the ones who know the most commands. They are the ones who understand why a security control exists, what risk it reduces, and how to operate it safely in production.

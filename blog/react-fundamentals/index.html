What is React?

React is a declarative JavaScript library for building component-based user interfaces. It was created by Meta and is maintained by Meta and the open-source community.

Important distinctions:

  • React is a library, not a full framework.
  • It concerns itself primarily with the view layer.
  • Routing, state management, and HTTP are handled by separate libraries.
  • React renders to a virtual DOM and updates the real DOM efficiently.

React can render to the web (react-dom), to native mobile via React Native, and to servers via server components and Node.js rendering.

Architecture and the Virtual DOM

The central concept in React is a component tree. When state changes, React:

1. Builds a new virtual DOM tree
2. Diffs (reconciles) it against the previous tree
3. Computes a minimal set of DOM mutations
4. Applies those mutations in a single batch

This "render, diff, commit" loop is what makes React predictable and efficient:

          React Component Tree
                   |
      +-----------------------+
      | Virtual DOM (current) |
      +-----------------------+
                   |
         Reconciliation / diffing
                   |
      +-----------------------+
      | Virtual DOM (new)     |
      +-----------------------+
                   |
            Commit phase
                   |
          Real DOM (updated)

Components, Props, and JSX

A component is a reusable, isolated piece of UI. Define one with a function:

function Welcome(props) {
  return <h1>Hello, {props.name}</h1>;
}

// or arrow form
const Welcome = (props) => (
  <h1>Hello, {props.name}</h1>
);

JSX lets you write HTML-like syntax in JavaScript:

<div className="card">
  <h2>{title}</h2>
  <p>{description}</p>
</div>
JSX compiles to React.createElement, which returns React elements — plain objects. At runtime React reads those objects and produces DOM nodes. This is why JSX is optional but strongly recommended for readability.

Composition with children

function Card({ title, children }) {
  return (
    <div className="card">
      <h2>{title}</h2>
      {children}
    </div>
  );
}

// Usage: props.children is injected between the tags
<Card title="Welcome">
  <p>Body content</p>
</Card>

State, Hooks, and Lifecycle

Components manage their own state with the useState Hook:

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}

Side effects and lifecycle are handled by useEffect:"

import { useState, useEffect } from 'react';

function Timer() {
  const [now, setNow] = useState(() => new Date());

  useEffect(() => {
    const id = setInterval(() => setNow(new Date()), 1000);
    return () => clearInterval(id); // cleanup on unmount
  }, []);

  return <time>{now.toLocaleTimeString()}</time>;
}

Common Component Patterns

Container / Presentational split

Separate logic from markup. The container owns state and behavior; the presentational component receives data via props.

// Presentational
function UserList({ users, onEdit }) {
  return (
    <ul>
      {users.map(u => (
        <li key={u.id}>
          {u.name} <button onClick={() => onEdit(u)}>Edit</button>
        </li>
      ))}
    </ul>
  );
}

// Container
function UserContainer() {
  const [users, setUsers] = useState([]);
  const onEdit = (u) => navigate(`/users/${u.id}`);
  useEffect(() => { fetchUsers().then(setUsers); }, []);
  return <UserList users={users} onEdit={onEdit} />;
}

Custom Hooks

Reuse stateful logic across components:

function useForm(initial) {
  const [values, setValues] = useState(initial);
  const handleChange = (e) =>
    setValues({ ...values, [e.target.name]: e.target.value });
  const reset = () => setValues(initial);
  return { values, handleChange, reset };
}

HOC and render props

Still useful for cross-cutting concerns such as authentication gating:

function withAuth(Component) {
  return function Authenticated(props) {
    const { user } = useContext(AuthContext);
    return user ? <Component {...props} /> : <Login />;
  };
}
Modern rule of thumb: prefer Custom Hooks over render props and higher-order components. They are simpler to read, easier to type with TypeScript, and easier to debug.

Routing: React Router

import { BrowserRouter, Routes, Route, Link, useParams, useNavigate } from 'react-router-dom';

function App() {
  return (
    <BrowserRouter>
      <nav>
        <Link to="/">Home</Link>
        <Link to="/users/1">User 1</Link>
      </nav>
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="users/:id" element={<User />} />
        <Route path="*" element={<NotFound />} />
      </Routes>
    </BrowserRouter>
  );
}

function User() {
  const { id } = useParams();
  // fetch user by id...
  return <h1>User {id}</h1>;
}

Data Fetching

Fetch inside useEffect, or in React 18+ with Suspense boundaries:

import { useState, useEffect } from 'react';

function Todos() {
  const [todos, setTodos] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch('/api/todos')
      .then((res) => res.json())
      .then((data) => setTodos(data))
      .catch((err) => setError(err))
      .finally(() => setLoading(false));
  }, []);

  if (loading) return <p>Loading…</p>;
  if (error) return <p>Error: {error.message}</p>;
  return <ul>{todos.map(t => <li key={t.id}>{t.title}</li>)}</ul>;
}

Choosing guidance: React is the safest choice when you need a large ecosystem, frequent hiring, SSR via Next.js, or React Native for mobile. Angular suits large Enterprise Java/.NET teams that want a batteries-included framework. Vue is ideal when you want approachable progressive adoption. Svelte is best for performance-first or bandwidth-constrained applications.

Conclusion

React is a small, fast, component-based view library. Its power comes from a vast ecosystem and the discipline of hooks and unidirectional data flow. Master the fundamentals — components, props, state, effects, and composition — and the rest of the ecosystem becomes straightforward to adopt.

Do not chase every library. Pick one routing solution (React Router or Next.js), one state story (useState/context locally, one global store for cross-component state), one styling approach (CSS Modules or Tailwind), and one testing strategy (React Testing Library). Consistency is what turns tooling into reliability in production.
